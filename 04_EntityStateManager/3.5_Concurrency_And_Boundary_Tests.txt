## 3. 禁止事项（硬性约束）

1. **测试反射泄漏红线**：测试代码必须且仅能通过 `EntityStateManager` 的公开 API 读写数据，严禁通过 Java 反射或访问私有锁实例（如 `transactionMutex` 的内部等待队列），防止测试深度耦合实现细节。

2. **脏数据流核对遗漏红线**：并发压力测试之后，必须订阅并核对 `stateDiffFlow` 发出的脏 ID 列表，校对其与实际发生变更的实体 ID 之间的完全匹配性，严禁跳过此步骤，防止脏标记丢失缺陷被遗漏隐匿。

3. **禁止全局粗锁替代槽锁**：单实体字段更新必须使用 `computeIfPresent` 槽位锁，禁止用 `transactionMutex` 替代。

4. **禁止超时死锁**：150 并发协程必须在 3 秒内完成，否则视为死锁或 Starvation 缺陷。

### 4.1 测试原则

### 4.2 测试用例

**T01：150 并发全局混合物资守恒压测**

- 目的：验证极高并发下物质守恒律、金币守恒与脏流完整性
- 初始化：
  - 注册村民 1，背包 `{"WOOD" to 1000}`
  - 注册仓库 2，容量 2000，库存 WOOD=0
  - 全局金币 1000
- 启动 150 并发协程（全部运行于 `Dispatchers.Default`）：
  - **负载 A**（50 协程）：高频并发执行 `transferItemVillagerToWarehouse(villagerId=1, warehouseId=2, item="WOOD", amount=2)`，记录成功次数 N_success
  - **负载 B**（50 协程）：高频交叉执行 `updateVillagerEnergy(id=1, 50)`，随机调用 `updatePlayerGold(-5)` 和 `updatePlayerGold(+5)` 震荡金币
  - **负载 C**（50 协程）：独立对仓库 2 执行 `updateWarehouseInventory(id=2, "WOOD", +1)` 写入干扰，记录总增量 C_delta
- 调用 `joinAll()` 等待所有并发任务完毕
- 断言 1（全局防死锁）：150 个协程必须在 3 秒内顺利完成，绝无线程死锁或 Starvation
- 断言 2（物质守恒律）：
  - 获取村民 1 背包 WOOD：V_wood
  - 获取仓库 2 库存 WOOD：W_wood
  - 核验：V_wood == 1000 - 2 * N_success（负载 A 成功次数下扣准确）
  - 核验：W_wood == 2 * N_success + C_delta（仓库收入两路来源均完整无漏）
- 断言 3（脏流完整性）：
  - 调用 `emitStateDiff()` 触发发射
  - 订阅 `stateDiffFlow`
  - 验证变更名单中村民 ID 1 与仓库 ID 2 均存在
  - 脏标记插桩零丢失

## 8. 语义级冻结声明

当本 MDU 及其配套测试完全通过后，`EntityStateManager` 核心语义冻结。

### 8.1 冻结语义边界

1. **原子槽位更新锁定**：单实体字段的原子更新必须通过 `computeIfPresent` 槽位锁机制，禁止使用全局粗锁替代。

2. **跨实体事务 Mutex 隔离**：跨实体资源调拨必须在 `transactionMutex.withLock` 下串行执行，确保物质守恒律物理成立。

3. **脏流标记不丢失**：每一次写操作成功后必须插桩 dirtySet，`emitStateDiff()` 被调用后必须精确发射所有被修改实体的 ID。

### 8.2 允许进化范围 (Permitted Evolutions)

- 允许在实体快照类中扩展新字段（如 `moodLevel` 情绪值）
- 扩展字段的并发读写必须沿用已建立的 `computeIfPresent` 原子槽锁规范
- 写操作后必须同样触发 dirtySet 插桩
