## 1. 24 小时时段换算契约（不可更改）

### 1.1 时段判定规则

**MORNING**：tickId % 24 == 1
**DAYTIME**：tickId % 24 in 2..14
**TWILIGHT**：tickId % 24 in 15..16
**NIGHT**：tickId % 24 in 17..23 或 tickId % 24 == 0（含 tickId=0 初始状态）

### 1.2 换算函数实现

```kotlin
private fun calculateTimePeriod(tickId: Long): TimePeriod {
    val remainder = Math.floorMod(tickId, 24L)
    return when (remainder) {
        1L -> TimePeriod.MORNING
        in 2..14L -> TimePeriod.DAYTIME
        in 15..16L -> TimePeriod.TWILIGHT
        else -> TimePeriod.NIGHT  // 0 或 17..23
    }
}
行为约束：

使用 tickId % 24 取余，确保余数始终在 [0, 23] 范围内
tickId 为负数时需用 Math.floorMod(tickId, 24) 替代以确保正余数
when 分支必须穷举所有 24 种情况或使用 else 兜底

2. 累加器与事件发射循环
2.1 累加器变量声明
kotlin复制// 在 TickEngine 类内部声明（MDU 1.1~1.3 的原子变量之后）
private var accumulator = 0L  // 用于追踪自上一 Tick 以来的累积毫秒数
2.2 while 循环内完整逻辑
```kotlin
fun start(initialTick: Long = 0) {
    startMutex.withLock {
        stopInternal()
        currentTickId.set(initialTick)
        accumulator = 0L // 重置累加器
        isEnginePaused.set(false)
        isLogicPaused.set(false)

        engineJob = scope.launch {
            while (isActive) {
                delay(50L)

                // === UI 高频心跳（MDU 1.2）===
                if (!isEnginePaused.get()) {
                    _realTickFlow.tryEmit(System.currentTimeMillis())
                }

                // === 逻辑心跳变速累加（MDU 1.4）===
                // 注意：即使 isEnginePaused == true，累加器仍继续累加，保证恢复时的时间精度
                accumulator += 50L
                val currentInterval = intervalMs.get()

                if (accumulator >= currentInterval) {
                    accumulator %= currentInterval  // 取模保留余数，不清零

                    // 只有在引擎和逻辑均未暂停时才发射 Tick
                    if (!isEnginePaused.get() && !isLogicPaused.get()) {
                        val newTick = currentTickId.incrementAndGet()
                        val timePeriod = calculateTimePeriod(newTick)
                        val event = TickEvent(
                            tickId = newTick,
                            timestamp = System.currentTimeMillis(),
                            timeOfDay = timePeriod
                        )
                        _tickFlow.tryEmit(event)
                    }
                }
            }
        }
    }
}
2.3 累加器行为约束（重要）
⚠️ 暂停期间累加器不得重置：当 isLogicPaused == true 时，累加器继续累积 +50L，但不清零。若重置累加器会导致恢复后额外等待一整个 intervalMs。
正常运行：accumulator += 50L，达到 intervalMs 时发射并取模
isLogicPaused == true：accumulator += 50L 继续，但不发射，accumulator 保留
isEnginePaused == true：整个 while 循环的 delay 照常执行，但两个 Flow 均不发射
resumeLogic() 后：accumulator 继承暂停前的值，继续累加
防突变积压：使用 `accumulator %= currentInterval` 而非 `= 0L`，保留余数以维持时间精度。
动态变速时的余数保留：当调用 `setGameSpeed` 改变 `intervalMs` 时，`accumulator` 的当前值不重置，并在下次 Tick 检查时直接按新的 `currentInterval` 取模。例如间隔从 5000 变为 500，累加器为 4800，取模后直接变为 300，导致逻辑 Tick 迅速响应。这是预期的“即时反应”行为。

3.3 setGameSpeed(newIntervalMs: Long)
```kotlin
fun setGameSpeed(newIntervalMs: Long) {
    if (newIntervalMs <= 0L) return // 遵循 MDU 1.1 契约：忽略非正值
    val clamped = newIntervalMs.coerceIn(500L, 60_000L) // 业务上下限钳位
    intervalMs.set(clamped)
}
```
边界约束：

下限 500ms：防止过高频心跳导致 CPU 过载
上限 60,000ms：防止误设超大值导致游戏心跳实质失效
无效值处理：小于等于 0 被忽略，超出 500~60000 区间的正数值会被 `coerceIn` 自动钳位到最近的边界值。

4. 双轨行为总览
isEnginePaused == true：

realTickFlow：不发射
tickFlow：不发射
accumulator：+= 50L 继续

isLogicPaused == true：

realTickFlow：照常发射
tickFlow：不发射
accumulator：+= 50L 继续

isEnginePaused == false 且 isLogicPaused == false：

realTickFlow：发射
tickFlow：达到间隔时发射
accumulator：达标时取模重置

5. 禁止事项（硬性约束）

累加器重置红线：pauseLogic() 期间严禁重置 accumulator，违者导致恢复后额外等待一整个 intervalMs
业务数据混入红线：realTickFlow 只携带 Long（毫秒时间戳），禁止携带 TickEvent
时段换算硬编码红线：禁止硬编码 tickId == 1 判断，必须使用 tickId % 24 == 1

9. 快速行为查阅
累加器状态转移：

启动 → accumulator = 0
每 50ms → accumulator += 50
accumulator >= intervalMs → accumulator %= intervalMs，发射 Tick
暂停逻辑 → accumulator 继续累加，不清零
恢复逻辑 → accumulator 继承暂停前值

时段判定：

tickId=0 → NIGHT
tickId=1 → MORNING
tickId=2…14 → DAYTIME
tickId=15…16 → TWILIGHT
tickId=17…23 → NIGHT

变速逻辑：

正常速度 5000ms → 每 5 秒一个逻辑 Tick
加速 1000ms → 每 1 秒一个逻辑 Tick
