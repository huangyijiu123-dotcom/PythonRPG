# MDU 3.2: 单体属性并发原子更新与边界静默截断

## 任务目标

为 `EntityStateManager` 实现所有活体单位（村民、冒险者、商队）和仓库/装备等单体属性的并发安全局部更新、数值静默截断及属性映射。

**输出标准**：所有更新操作必须在 `ConcurrentHashMap.computeIfPresent` 槽锁内完成，禁止先 get 再 copy 再 put 的非原子模式。数值边界必须静默截断，集合操作必须防御性拷贝。

## 2. 机械式步骤指令

### 2.1 静默数值边界处理

所有数值更新必须在 `computeIfPresent` 闭包内完成截断：

**村民 energy**：`newEnergy.coerceIn(0, 100)`
**冒险者 hp**：`newHp.coerceIn(0, old.maxHp)`
**冒险者 mp**：`newMp.coerceIn(0, 100)`
**冒险者 fatigue**：`newFatigue.coerceIn(0, 100)`
**装备 level**：`newLevel.coerceIn(0, 10)`
**装备 durability**：`newDurability.coerceIn(0, old.maxDurability)`

### 2.2 仓库库存更新完整逻辑

```kotlin
var isSuccess = true
warehouses.computeIfPresent(id) { _, old ->
    val currentTotalStock = old.inventory.values.sum()
    val currentQty = old.inventory[item] ?: 0
    val finalQty = currentQty + amount

    // 边界校验：数量不能为负，且总库存不能超限
    if (finalQty < 0 || currentTotalStock + amount > old.capacity) {
        isSuccess = false
        old // 校验失败返回原对象，不发生任何修改
    } else {
        val newInv = old.inventory.toMutableMap()
        if (finalQty == 0) {
            newInv.remove(item)
        } else {
            newInv[item] = finalQty
        }
        old.copy(inventory = newInv)
    }
}
return isSuccess
```

### 2.3 商队货物更新逻辑

遵循与仓库完全一致的 `computeIfPresent` 负数保护机制，但不做总容量限制（总容量限制在 MDU 3.4 事务中专门校验）。

### 2.4 仓库容量扩充逻辑

- 必须通过 `additionalCapacity > 0` 检查，不合规时直接返回 `false`
- 通过 `computeIfPresent` 将 `capacity` 累加 `additionalCapacity`

## 3. 禁止事项（硬性约束）

1. **丢失更新覆盖红线**：绝对禁止"先 get 出来，外部 copy 修改，最后 put 写入"的非原子更新方法。例如：
   ```kotlin
   // 禁止以下模式：
   val old = villagers[id]
   if (old != null) { villagers[id] = old.copy(x = newX) }
   ```
   所有方法必须在并发容器的 `computeIfPresent` 槽锁内原子更新。

2. **集合修改现场污染**：对于所有 Map 类型属性（backpack, cargo, inventory, equippedTools），拷贝时必须使用 `toMutableMap()` 创建新集合，禁止直接在旧引用上修改。

3. **禁止容量越界**：仓库总库存严格不能超过 capacity，超出时必须返回 false 且保持原状态。

4. **禁止负数库存**：任何扣减导致数量 < 0 的操作必须返回 false 且保持原状态。

## 4. 测试规范：EntityStateManagerUpdateTest.kt

### 4.1 测试原则

⚠️ 黑盒测试强制规则：禁止使用反射或访问内部容器字段。所有验证必须通过公开 API 反映。

### 4.2 测试用例

**T01：村民与冒险者数值静默截断测试**

- 目的：验证数值边界自动截断行为
- 步骤：
  1. 注册村民 1（energy = 80）
  2. 注册冒险者 2（hp = 80, maxHp = 150, fatigue = 20）
  3. 调用 `updateVillagerEnergy(1, 999)` → 断言返回 true，energy == 100
  4. 调用 `updateAdventurerHp(2, 200)` → 断言返回 true，hp == 150
  5. 调用 `updateAdventurerFatigue(2, -50)` → 断言返回 true，fatigue == 0
- 通过标准：所有数值正确截断到边界

**T02：并发背包与货物增减零丢失测试**

- 目的：验证 computeIfPresent 槽锁的并发安全性
- 步骤：
  1. 注册村民 1，背包设为 `{"WOOD" to 100}`
  2. 并发启动 50 个协程调用 `updateVillagerBackpackItem(1, "WOOD", 5)`
  3. 并发启动 50 个协程调用 `updateVillagerBackpackItem(1, "WOOD", -2)`
  4. 等待所有并发结束
  5. 断言 `"WOOD"` 数量最终精准为 250（100 + 50*5 - 50*2）
- 通过标准：无并发状态丢失

**T03：仓库容量满限与负数回滚测试**

- 目的：验证容量限制和负数保护
- 步骤：
  1. 注册容量为 500 的仓库 1，初始库存 `{"STONE" to 495}`
  2. 调用 `updateWarehouseInventory(1, "STONE", 10)`（总库存将达 505，超限）
  3. 断言 1：返回 false，写入被拦截
  4. 断言 2：`getWarehouse(1)?.inventory?.get("STONE")` 仍为 495
  5. 调用 `updateWarehouseInventory(1, "STONE", -500)`（超额扣减）
  6. 断言：返回 false，库存保持 495
- 通过标准：超限和负数均被正确拦截

**T04：工具耐久归零自动移除测试**

- 目的：验证耐久归零时工具自动从 Map 移除
- 步骤：
  1. 注册村民 1
  2. 调用 `equipTool(1, "IRON_AXE", 100)`
  3. 调用 `updateToolDurability(1, "IRON_AXE", 0)`
  4. 断言：`equippedTools` Map 中不含 `"IRON_AXE"` 键
- 通过标准：耐久归零后工具完全移除

## 8. 快速行为查阅

**数值截断时序**：
```
updateVillagerEnergy(id, 999)
  → computeIfPresent { old -> old.copy(energy = 999.coerceIn(0, 100)) }
  → energy 实际设为 100
  → 返回 true
```

**背包并发更新时序**：
```
updateVillagerBackpackItem(id, "WOOD", 5)
  → computeIfPresent { old ->
      val newBackpack = old.backpack.toMutableMap()
      newBackpack["WOOD"] = (newBackpack["WOOD"] ?: 0) + 5
      old.copy(backpack = newBackpack)
    }
  → 返回 true
```

**仓库容量拦截时序**：
```
updateWarehouseInventory(id, "STONE", 10)
  → computeIfPresent { old ->
      val total = old.inventory.values.sum()
      if (total + 10 > old.capacity) { isSuccess = false; old }
      else { /* 更新库存 */ }
    }
  → 容量超限返回 false，状态不变
```

**工具耐久归零时序**：
```
updateToolDurability(id, "IRON_AXE", 0)
  → computeIfPresent { old ->
      val newTools = old.equippedTools.toMutableMap()
      newTools.remove("IRON_AXE")
      old.copy(equippedTools = newTools)
    }
  → 工具从 Map 移除
```
