## 2. 机械式步骤指令与禁止事项

### 禁止事项：
1. **防部分更新数据撕裂红线 (Dirty Writes & Partial Commits)**：
   **绝对禁止**将两个实体的更新作为独立的隔离操作执行而没有全程加锁保护！
   如果直接使用两个连续的 `computeIfPresent`：
   `villagers.computeIfPresent(...)` 然后 `warehouses.computeIfPresent(...)`
   在高并发场景下，如果第一个操作成功而第二个由于仓库超容（Capacity Overflow）返回 false，已扣除的村民背包物资将彻底凭空蒸发，形成严重的数据撕裂 bug。
2. **禁止参数非法溢出**：所有的 `amount` 参数必须大于 0。若 `amount <= 0` 直接返回 `false`。

### 机械式步骤指令：
1. **声明全局事务互斥锁**：在 `EntityStateManager` 类内部定义全局私有协程锁：
   `private val transactionMutex = Mutex()`
2. **实现 `suspend fun transferItem*` 事务系列**：以 `transferItemVillagerToWarehouse` 为例，严格遵循**"互斥锁定 -> 实体存在校验 -> 资源储量校验 -> 目标容量校验 -> 原子双写"**的安全事务流：
   - 步骤 A：使用协程互斥锁包裹整个执行体：
     ```kotlin
     if (amount <= 0) return false
     return transactionMutex.withLock {
         // 以下操作处于全局互斥排他保护中
     }
     ```
   - 步骤 B：**前置校验**（若任何一项不满足，直接返回 `false`，不产生任何修改）：
     - 校验 1：村民是否存在？`val villager = villagers[villagerId] ?: return false`
     - 校验 2：仓库是否存在？`val warehouse = warehouses[warehouseId] ?: return false`
     - 校验 3：村民背包是否有足够物资？`val currentQty = villager.backpack[item] ?: 0; if (currentQty < amount) return false`
     - 校验 4：目标仓库加上物资后是否会超出其最大容量？
       `val currentTotalStock = warehouse.inventory.values.sum()`
       `if (currentTotalStock + amount > warehouse.capacity) return false`
   - 步骤 C：**原子安全写入**（由于已经锁定了整个转移事务且完成了所有安全性校验，此处的写操作绝不可能触发失败，可以使用普通的 `copy` + `put` 安全填回 Map）：
     - 扣减村民背包：
       ```kotlin
       val newBackpack = villager.backpack.toMutableMap()
       val remaining = currentQty - amount
       if (remaining == 0) newBackpack.remove(item) else newBackpack[item] = remaining
       villagers[villagerId] = villager.copy(backpack = newBackpack)
       ```
     - 累加仓库库存：
       ```kotlin
       val newInventory = warehouse.inventory.toMutableMap()
       newInventory[item] = (newInventory[item] ?: 0) + amount
       warehouses[warehouseId] = warehouse.copy(inventory = newInventory)
       ```
     - 返回 `true`。

## 2. 机械式步骤指令

### 2.1 声明全局事务互斥锁

在 `EntityStateManager` 类内部定义全局私有协程锁：

```kotlin
private val transactionMutex = Mutex()
```

### 2.2 实现安全事务流

所有 `transferItem*` 方法必须严格遵循以下安全事务流：

**互斥锁定 → 实体存在校验 → 资源储量校验 → 目标容量校验 → 原子双写**

以 `transferItemVillagerToWarehouse` 为例：

```kotlin
suspend fun transferItemVillagerToWarehouse(
    villagerId: Long,
    warehouseId: Long,
    item: String,
    amount: Int
): Boolean {
    if (amount <= 0) return false
    
    return transactionMutex.withLock {
        // 步骤 B：前置校验（任何一项不满足直接返回 false，不产生修改）
        
        // 校验 1：村民是否存在
        val villager = villagers[villagerId] ?: return@withLock false
        
        // 校验 2：仓库是否存在
        val warehouse = warehouses[warehouseId] ?: return@withLock false
        
        // 校验 3：村民背包是否有足够物资
        val currentQty = villager.backpack[item] ?: 0
        if (currentQty < amount) return@withLock false
        
        // 校验 4：目标仓库加上物资后是否超容
        val currentTotalStock = warehouse.inventory.values.sum()
        if (currentTotalStock + amount > warehouse.capacity) return@withLock false
        
        // 步骤 C：原子安全写入（校验已通过，写操作不可能失败）
        
        // 扣减村民背包
        val newBackpack = villager.backpack.toMutableMap()
        val remaining = currentQty - amount
        if (remaining == 0) newBackpack.remove(item) else newBackpack[item] = remaining
        villagers[villagerId] = villager.copy(backpack = newBackpack)
        
        // 累加仓库库存
        val newInventory = warehouse.inventory.toMutableMap()
        newInventory[item] = (newInventory[item] ?: 0) + amount
        warehouses[warehouseId] = warehouse.copy(inventory = newInventory)
        
        true
    }
}
```

### 2.4 仓库到商队转移

- 校验源头仓库是否有足够物资：`warehouse.inventory[item] ?: 0 >= amount`
- 校验商队累加后是否超容：`caravan.cargo.values.sum() + amount > caravan.capacity`
- 校验通过后：扣减仓库 inventory，累加商队 cargo

## 3. 禁止事项（硬性约束）

1. **防部分更新数据撕裂红线**：绝对禁止将两个实体的更新作为独立隔离操作执行而没有全程加锁保护。

   **禁止以下模式**：
   ```kotlin
   // 危险：两个独立 computeIfPresent 无全局锁保护
   villagers.computeIfPresent(villagerId) { /* 扣减背包 */ }
   warehouses.computeIfPresent(warehouseId) { /* 累加库存 */ }
   ```
   
   高并发下若第一个成功而第二个因超容返回 false，已扣除的村民背包物资将凭空蒸发，形成严重数据撕裂 bug。

2. **禁止参数非法溢出**：所有 `amount` 参数必须大于 0。若 `amount <= 0` 直接返回 `false`。

3. **禁止无锁双写**：必须先通过 `transactionMutex.withLock` 获取全局锁，再在锁内完成所有校验和双写操作。

4. **禁止部分提交**：前置校验阶段任何一项失败必须立即返回 false，不能执行任何修改。

  → transactionMutex.withLock {

      warehouse = warehouses[2] ?: return false
      currentQty = villager.backpack["WOOD"] ?: 0
      if (currentQty < 10) return false
      if (warehouse.inventory.values.sum() + 10 > warehouse.capacity) return false
      // 校验全部通过
      villagers[1] = villager.copy(backpack = newBackpack)
      warehouses[2] = warehouse.copy(inventory = newInventory)
      return true
    }
  → 返回 true
```

**事务失败回滚时序**：
```
