## 2. 类骨架与核心存储

### 2.1 骨架声明

```kotlin
class GridMapData {
    // 核心底层存储（见 2.2）
    // 坐标压缩辅助方法（见 2.3）
    // 基础读写 API（见 3）
    // 禁止：区域查询、批量锁、序列化逻辑、dirtyQueue
}
```

### 2.2 核心底层存储

```kotlin
private val tileMap = ConcurrentHashMap<Long, TileData>()
```

**设计约束**：
- 使用 `ConcurrentHashMap` 确保基本线程安全
- 避免预分配物理网格大小以支持无限世界
- Key 类型为 `Long`（压缩后的坐标），禁止直接使用 `Coordinate` 对象作为键

### 2.3 高性能坐标压缩

```kotlin
private fun packToLong(x: Int, y: Int): Long = 
    (x.toLong() shl 32) or (y.toLong() and 0xFFFFFFFFL)
```

**设计约束**：
- 利用位位移操作将二维 x, y 坐标合并为一个 Long
- 作为 `ConcurrentHashMap` 的 Key
- 严禁在底层 Map 中直接使用 `Coordinate` 对象作为键，规避成千上万临时对象创建带来的巨大 GC 压力

## 3. 基础读写 API

### 3.1 setTile(tile: TileData)

**签名**：fun setTile(tile: TileData)

**功能**：将 TileData 存入底层存储

**实现**：
```kotlin
fun setTile(tile: TileData) {
    val key = packToLong(tile.coordinate.x, tile.coordinate.y)
    tileMap[key] = tile
}
```

### 3.2 getTile(x: Int, y: Int): TileData?

**签名**：fun getTile(x: Int, y: Int): TileData?

**功能**：根据坐标查询 TileData

**实现**：
```kotlin
fun getTile(x: Int, y: Int): TileData? {
    val key = packToLong(x, y)
    return tileMap[key]
}
```

**行为约束**：坐标不存在时返回 null

### 3.3 size(): Int

**签名**：fun size(): Int

**功能**：返回当前存储的格子数量

**实现**：
```kotlin
fun size(): Int = tileMap.size
```

**行为约束**：
- `ConcurrentHashMap.size` 返回弱一致性值（高并发写入期间可能有轻微误差）
- 对于调试统计场景完全可接受
- 无需加 `batchMutex`

### 3.4 clear()

**签名**：fun clear()

**功能**：清空格子存储

**实现**：
```kotlin
fun clear() = tileMap.clear()
```

**行为约束**：
- 本阶段仅负责清空 `tileMap`
- 脏坐标队列 `dirtyQueue` 的清空职责在 MDU 2.5 的 `importFromJson` 中统一处理
- 禁止在此阶段引用 `dirtyQueue`

## 4. 禁止事项（硬性约束）

1. **禁止 Coordinate 作为 Map 键**：底层 Map 必须使用 `Long` 类型键（压缩后的坐标），禁止直接使用 `Coordinate` 对象作为键。

2. **禁止预分配网格**：避免预分配物理网格大小，支持无限世界扩展。

3. **禁止引用未声明组件**：本阶段禁止引用 `dirtyQueue`、`batchMutex` 等尚未声明的组件。

4. **禁止加锁 size()**：`size()` 直接返回 `tileMap.size`，无需加锁。

## 2. 机械式步骤指令 (Mechanical Instructions)

1. **定义基础模型**：在同一文件或合适包下声明 `Coordinate` 数据类、`ExploreStatus` 枚举以及 `TileData` 数据类。
2. **定义数据类骨架**：创建 `class GridMapData`。
3. **声明核心底层存储**：在类内部定义 `private val tileMap = ConcurrentHashMap<Long, TileData>()`，使用 `ConcurrentHashMap` 确保基本的线程安全，避免预分配物理网格大小以支持无限世界。
4. **实现高性能坐标压缩**：声明私有辅助方法 `private fun packToLong(x: Int, y: Int): Long = (x.toLong() shl 32) or (y.toLong() and 0xFFFFFFFFL)`。该方法利用位位移操作，直接将二维 `x, y` 坐标合并为一个 Long，从而作为 `ConcurrentHashMap` 的 Key。
   > [!IMPORTANT]
   > 严禁在底层 Map 中直接使用 `Coordinate` 对象作为键，这能够规避成千上万临时对象创建带来的巨大 GC 压力。
5. **声明/实现基础读写 API**：
   - 实现 `fun setTile(tile: TileData)`：将 `tile.coordinate.x` 与 `y` 用 `packToLong` 压缩为 Key，存入 `tileMap`。
   - 实现 `fun getTile(x: Int, y: Int): TileData?`：将坐标压缩后，直接查询并返回 `tileMap` 中的对应对象。如果不存在，直接返回 `null`。
   - 实现 `fun size(): Int`：直接返回 `tileMap.size`。
     > [!NOTE]
     > `ConcurrentHashMap.size` 返回的是弱一致性值（在高并发写入期间可能有轻微误差），但这对于调试统计场景完全可接受。**无需加 `batchMutex`**。
   - 实现 `fun clear()`：仅调用 `tileMap.clear()` 清空格子存储。
     > [!NOTE]
     > 本阶段的 `clear()` **只负责清空 `tileMap`**。脏坐标队列 `dirtyQueue` 的清空职责在 MDU 2.5 的 `importFromJson` 中统一处理（因为 dirtyQueue 在本阶段尚未声明）。AI 实现时不要在此阶段引用 dirtyQueue。
