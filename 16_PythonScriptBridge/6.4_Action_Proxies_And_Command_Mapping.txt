## 2. 指令超限拦截与熔断规约 (Command Flood Protection)

### 禁止事项：
1. **指令泛滥挂死宿主红线 (Command Flood Prevention)**：
   **绝对禁止**玩家通过 Python 编写失控的 `for` 循环生成成千上万个指令塞爆 `ActionProcessor` 缓冲队列！
2. **截断规约**：单次脚本执行产生的 `PlayerCommand` **最大上限强制锁定为 200 个**。一旦 `commandBuffer.size` 达到 200，后续所有的代理动作方法调用直接静默拦截不予写入，并自动在最终的 `ScriptResult.errorMessage` 追加 `👴 村长警告：大人在此 tick 下达的策略指令已超过 200 个最大负荷！超出的命令已被强力截断。` 提示，保障引擎并发安全性。

### 机械式步骤指令：
1. 在所有 Proxy 动作方法的写入开头添加超载过滤：
   ```kotlin
   if (commandBuffer.size >= 200) {
       // 触发超载熔断，直接返回
       return
   }
   ```
2. 脚本运行结束后，在 Kotlin 侧通过：
   `val finalCommands = commandBuffer.take(200)`
   将其批量推送给 `ActionProcessor.enqueueCommand(cmd)`。

## MDU 6.4-TEST: 指令生成与超限熔断黑盒测试

编写单元测试 `PythonCommandGenerationTest.kt`。

### 机械式测试用例：
1. **动作代理翻译指令精准性测试**：
   - 实例化 `VillagerProxy`，传入 `id = 5`，状态为休息。
   - 在 Python 环境下执行：`v.assign_job("FARMING", 10, 20)`。
   - **断言 1**：共享的 `commandBuffer` 队列中多出了一个元素。
   - **断言 2**：多出的元素类型精准为 `PlayerCommand.AssignJob`，其中 `villagerId == 5`，`job == "FARMING"`，坐标为 `(10, 20)`。
2. **工具换装仓库定位匹配测试**：
   - 设定快照中仓库 1 存有 `{"IRON_AXE" to 1}`（在 `(2, 2)`），仓库 2 存有 `{"IRON_AXE" to 5}`（在 `(0, 0)`）。
   - 初始化村民在 `(1, 1)`（距离仓库 1 曼哈顿距离为 2，距离仓库 2 为 2，选择 ID 较小的 1）。
   - 调用 `v.equip_tool("IRON_AXE")`。
   - **断言 1**：方法返回 `true`。
   - **断言 2**：`commandBuffer` 产生一条 `PlayerCommand.EquipTool(5, "IRON_AXE", 1L)` 指令。
3. **指令超限 200 熔断截断测试**：
   - 在 Python 沙箱中执行狂暴投递脚本：
     ```python
     for i in range(500):
         v.assign_job("MINING", 1, 1)
     ```
   - **断言 1**：`ScriptResult.success` 返回 `true`。
   - **断言 2**：`commandsEnqueued`（排队指令数）精准等于 `200`，绝不超出。
   - **断言 3**：`errorMessage` 文本中包含 `"村长警告"` 且包含 `"超出的命令已被强力截断"`。

只包含 `VillagerProxy`、`CaravanProxy`、`BuildingProxy` 的动作映射方法完善实现、200 指令上限静默熔断机制、及对应指令生成和超量截断 JUnit 单元测试。不含 AST 检查、全局 Context 查询及村长异常翻译模块。
